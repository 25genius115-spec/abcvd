## 현재 인증 방식 — 사이트 카메라 3회 촬영

제품 선택 → 기준 판매 이미지 표시 → 손에 들고 앞면 촬영 → 서버가 무작위로 정한 두 방향 촬영 → 세 장 확인 → Gemini 1회 분석 → 제품·방향 일치 시 임시 인증 → 정원 반영.

일반 인증에서 숫자 종이·바코드·주문내역 업로드를 사용하지 않습니다. 판매 이미지가 없는 기존 제품은 Exa Contents로 해당 판매 페이지의 이미지 URL을 확인해 저장합니다. 이미지는 분석할 때만 메모리에서 사용하며 DB에 원본을 저장하지 않습니다. 기준 이미지와 촬영 세 장을 함께 비교하고, 구매 사실이나 촬영 장치를 확정하지 않습니다.

촬영 요청은 10분 동안 유효하며 사용자·제품·촬영 지시는 서버에 고정됩니다. 동일 사진 반복, 잘못된 방향, 불명확한 제품, 중복 인증은 차단합니다. AI 요청은 1280px 이내로 줄여 1회만 보내고 자동 재시도하지 않습니다. 504/시간 초과 시 사진을 유지하여 사용자가 다시 제출할 수 있습니다. 시간 만료 시에는 새로 촬영해야 합니다.

- `POST /verification/photo-challenge`: 로그인 토큰 + product_id → 기준 이미지와 촬영 지시 3개
- `POST /purchases/verify-photos`: 로그인 토큰 + product_id, challenge_id, photo_1, photo_2, photo_3
- `PHOTO_GUIDED`: 세 방향 촬영으로 완료한 임시 인증
- 개발자 테스트: 구매 인증의 ‘개발자 테스트’에서 별도 실행. `DEVELOPER_TEST`로 저장하며 실제 보상에서 제외
- 기존 바코드 API와 기존 구매 기록은 호환을 위해 유지

서버 시작 시 기존 데이터를 보존한 채 촬영 지시·AI 판정 기록용 열과 이미지 조회 제한 테이블을 추가합니다. 관리자 패널에서 촬영 지시와 판정을 확인할 수 있습니다. 새 코드 적용은 FastAPI와 Streamlit 재시작이 필요합니다.

이 문단이 아래의 과거 인증 방식 설명보다 우선합니다.

## 관리자 패널

개발 모드에서 woodglue 등 developer 계정으로 로그인하면 사이드바에 관리자 패널이 나타납니다. 사용자별 인증 결과/상품/GTIN/기여도 확인, 새 인증 시도의 실패 단계 조회, 선택 인증 초기화, 내 테스트 인증 일괄 초기화, 진행 중 번호 취소, 처리 이력을 제공합니다. 모든 관리자 API도 개발 모드와 역할을 검사합니다.

초기화는 인증 기록을 삭제하는 대신 revoked로 남기고 관련 기여도와 중복 제한을 해제합니다. 보상 심사는 구매 기록 변경에 따라 재확인이 필요합니다. 초기화는 확인 항목과 사유를 입력해야 실행되며 실제 기록에 자동 실행하지 않습니다. API 키·비밀번호·세션 토큰·원본 인증 이미지는 패널에 노출하지 않습니다. 오류 내역은 이 기능 추가 이후의 인증 요청부터 수집합니다.

## 이전 인증 방식 (한 장 자동 인증)

제품 선택 → 4자리 번호 발급 → 바코드와 번호를 함께 촬영 → Gemini 번호 판독 1회 → 서버 번호 대조 → OpenCV 체크섬 확인 → UPCitemdb/Exa 조회 → 정확한 제품명·브랜드 일치 시 임시 인증입니다. 일반 사용자의 주문내역 업로드는 제거했습니다. AI는 합성 여부나 구매 사실을 확정하지 않습니다. 불명확한 상품명·브랜드는 승인하지 않습니다.

번호는 5분 안에 제출하고 성공 시 1회 사용합니다. 실패 시 재촬영할 수 있으며 같은 이미지의 번호 판독 결과는 재사용합니다. 기존 verification_status='verified'는 집계 호환을 위해 유지하고 verification_stage='provisional'로 임시 상태를 구분합니다. 실제 구매일/금액은 알 수 없으므로 NULL입니다.

사용자·product_id와 사용자·정규화 GTIN은 verification_claims의 UNIQUE 제약과 purchases 트리거로 중복을 차단합니다. 기존 중복 구매를 삭제하지 않고 대표 인증 키를 등록합니다. 기존 계정·기여도 데이터는 유지합니다.

보상 후보는 개발자 테스트 구매를 제외하고 계산합니다. 월간 상위 후보만 별도 증빙을 제출하고 담당자가 구매 상품 목록/증빙을 직접 검토합니다. 탈락자를 제외하고 다음 순위를 심사하며, 승인 후 구매·환경 데이터가 바뀌면 다시 심사합니다. 증빙은 backend/reward_evidence에 저장되며 소유자와 개발 모드 담당자만 열람합니다. 실제 송금 API는 없고 심사 통과 금액만 구분합니다. 아래 과거 개발 내역보다 이 절의 현재 동작이 우선합니다.

# 🌱 초록선택 · 로컬 베타

웹검색은 Exa Deep Search, 사진 인증은 기존 Gemini를 사용합니다.
검색과 구조화 출력을 Exa 요청 한 번으로 받으며, 추천은 최대 5개입니다.
검색 원문의 URL·인용을 대조하고 가격·환경 수치는 확인된 경우에만 저장합니다.
동일 요청은 SQLite `exa_search_cache`에서 24시간 재사용합니다. 자동 재시도는 하지 않습니다.
단일 서버 프로세스에서 검색을 하나씩 처리하며 429 이후 재요청을 잠시 차단합니다.
QPS 10 설정은 그대로 둘 수 있습니다. 실제 판매 여부·정확도는 API 결과에 따라 달라집니다.

## 계정과 구매

회원가입 후 로그인합니다. 비밀번호는 Argon2 해시, 세션은 7일 유효 랜덤 토큰의 SHA-256 해시만 DB에 저장합니다. 원문 토큰은 로그인 응답과 현재 Streamlit 세션에만 유지합니다. 새 브라우저 세션에서는 다시 로그인합니다. 로그아웃하면 서버 세션과 화면의 개인 데이터를 지웁니다.

구매 인증 흐름은 제품 선택 → 주문내역 이미지 → 인증번호 발급 → 실제 제품과 번호 촬영 → Gemini 분석입니다. 인증된 구매의 환경 기록을 같은 트랜잭션에서 한 번만 생성합니다. 구매 한 건을 제품 한 개 기준으로 처리하며 수량 인식·환산은 하지 않습니다.

기존 데이터는 삭제하지 않습니다. 계정 확장 전 `backend/eco.before_accounts.db`로 백업합니다. 임시 사용자에는 비밀번호가 없어 로그인할 수 없으며 기존 기록은 그 ID에 보존됩니다. 이름이 같다고 새 계정으로 기록을 이전하지 않습니다.

## 환경 데이터 입력 위치

실제 데이터는 `backend/eco.db`의 `products` 테이블에 넣습니다. 연결 함수는 `backend/database.py`의 `get_connection()`입니다. 관리 UI나 자동 검색은 없습니다.

- `co2_saved_kg`: 제품 1개당 kgCO2e
- `plastic_saved_g`: 제품 1개당 g
- `water_saved_l`: 제품 1개당 L
- `impact_basis`: 비교 대상, 제품 1개 기준, 산정 범위 등
- `impact_source`: 검증한 출처 또는 URL
- `impact_verified`: 근거 확인 후에만 1

값을 알 수 없는 항목은 NULL로 둡니다. 기존 가상 제품에는 수치를 넣지 않았습니다. 검증 표시와 기준·출처가 모두 있는 제품만 수치를 스냅샷으로 기록합니다. `backend/impact.py`의 `record_impact()`가 저장, `get_summary()`와 `get_history()`가 조회를 담당합니다.

이미 기록된 구매는 제품 값을 바꿔도 자동 재계산하지 않습니다. 출처 없는 기존 환경 수치는 기존 열에 보존하지만 새 합계에는 포함하지 않습니다. 화면의 합계 0은 근거 있는 데이터가 없다는 뜻일 수도 있습니다. 구매일이 없는 기록은 전체 건수에는 포함하고 날짜 그래프에서는 제외합니다.

## 파일과 확장 위치

- `account_ui.py`: 로그인·회원가입 화면
- `streamlit_app.py`: 로그인 확인·로그아웃·메뉴
- `api_client.py`: 공통 Bearer 헤더와 API 함수

## 개발자 테스트 모드

FastAPI 실행 터미널에서 `export DEVELOPMENT_MODE=True`로 켭니다. 기본값은 False입니다. 시작 시 지정된 초기 비밀번호의 Argon2 해시로 `woodglue` 개발 계정을 한 번 생성합니다. 기존 일반 계정은 승격하지 않으며 개발 계정의 비밀번호도 재시작 때 덮어쓰지 않습니다.

```bash
source .venv/bin/activate
export DEVELOPMENT_MODE=True
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload
```

개발자 로그인 후 구매 인증 화면에서 제품을 선택하고 테스트 구매 인증을 누릅니다. 이 경로는 Gemini나 이미지를 사용하지 않으며 DEVELOPER_TEST 구매와 환경 기록을 한 트랜잭션으로 저장합니다. NULL 환경 값은 그대로 유지하며 구매 건수에는 반영됩니다. 같은 구매의 환경 기록은 중복 생성하지 않습니다.

테스트 데이터 초기화는 현재 개발자의 DEVELOPER_TEST 구매와 연결된 환경 기록만 지웁니다. 실제 AI 인증 구매와 다른 사용자의 기록은 유지합니다. 개발 모드를 끄면 개발자 역할이 있어도 테스트 API와 버튼을 사용할 수 없습니다. 모드 변경은 서버 재시작이 필요합니다.

관련 파일: `backend/developer_setup.py`(역할·계정 초기화), `backend/developer.py`(권한·테스트 저장·초기화), `backend/config.py`(개발 모드). 제품별 실제 환경 데이터 입력 위치는 기존 `backend/eco.db`의 products 테이블이며 impact_basis·impact_source·impact_verified와 단위별 수치를 함께 관리합니다.

## DOCX 기반 실제 제품 수집

Exa 키를 설정한 터미널에서 실행합니다. 제품 이미지는 다운로드하지 않습니다.

```bash
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python3 update_products.py
```

입력은 루트의 `친환경_대체품_목록.docx`이며 한글 파일명 정규화 차이도 처리합니다. 현재 문서는 분류·기존 제품별 대체품 64개입니다. 같은 대체품은 한 번만 검색하고 URL이 같은 제품은 한 번만 저장합니다. 같은 대체품이 여러 분류에 있으면 최초 항목을 사용합니다. 도보 등 판매 제품이 아닌 대체품은 결과가 없을 수 있습니다.

웹검색은 Exa Deep Search의 구조화 출력으로 한 번에 처리합니다. 별도 Groq 정리 호출 없이 출처 원문과 결과를 함께 받습니다. 구매 이미지 판정에는 기존 Gemini를 계속 사용합니다.

제품명은 기존 name, 친환경 설명은 eco_description에 저장합니다. 원화 가격이 확인되지 않으면 NULL, 이미지 주소를 확인하지 못하므로 image_url은 NULL로 둡니다. 공인 친환경 인증을 독립 확인하지 않으므로 eco_verified는 false입니다. 환경 기여도 수치는 채우지 않습니다. 수집 근거와 시각은 search_evidence와 collected_at에 남깁니다. 검색 시점 정보이며 이후 가격·재고는 달라질 수 있습니다.

DB 확장 전 eco.before_catalog.db로 백업하며 기존 ID와 구매 연결을 보존합니다. 실행 결과는 product_collection_report.json에 추출·저장·중복·실패 검색어 수로 저장합니다. 키가 없는 실행은 검색 실패가 아니라 blocked_missing_api_key로 기록합니다. 단일 검색 실패는 다음 검색을 중단하지 않습니다.

기존 Streamlit UI는 이 수집 단계에서 변경하지 않았습니다. 기존 제품 목록은 숫자 가격을 가정하므로 가격 NULL 제품을 화면에 표시하려면 별도의 최소 호환성 수정이 필요합니다.

### 추천

제품 찾기에서 일반 제품·조건·최대 가격을 입력합니다. Exa Deep Search 인용 근거에서 최대 5개 제품을 구조화 추출합니다. URL은 검색 출처에서만 가져오며 미확인 가격·브랜드·판매처는 비워 둡니다. 제품은 products, 검색 조건별 ID는 recommendation_cache에 저장합니다. 제품이 있는 검색은 24시간, 빈 결과는 15분 재사용합니다. 검색 출처 자체를 얻지 못한 실패는 캐시하지 않습니다.

Python 점수는 가격 40% + 친환경 특징 근거 40% + 인증 20%입니다. 결과 내 가격 min/max로 0~100 정규화하고, 동일 가격은 100점, 미확인 가격은 점수 기여 0입니다. 출처가 있는 반복사용·리필·재생소재·플라스틱 미사용 특징마다 25점, 해당 모델의 공식 인증 근거가 있으면 인증 100점입니다. 이는 서비스의 비교 규칙이며 공인 환경 점수가 아닙니다. 예산이 있어도 가격 미확인 제품은 별도 확인이 필요하다고 표시합니다.

### 제품과 인증번호 종이로 구매 인증

현재 인증은 주문내역과 제품·인증번호 종이 사진 2장을 사용합니다. 바코드 촬영·조회는 하지 않습니다. 서버가 발급한 4자리 숫자를 종이에 적고 제품과 함께 촬영하면 Gemini가 실제 제품·종이·숫자를 판독합니다. 정답 번호는 AI 입력에 넣지 않고 서버에서 판독 결과와 비교합니다. 계정당 같은 products.id 상품은 한 번만 인증할 수 있으며, 번호 발급/저장/DB 트리거에서 중복을 차단합니다. 기존 중복 기록은 삭제하지 않습니다.

### 환경 근거 조사

일반 AI 인증 성공 후 background task로 근거를 조사합니다. 인증 저장은 유지하고 조사 실패는 별도 상태로 표시합니다. 환경 화면의 새로고침으로 결과를 보고 실패·미조사 건은 다시 요청할 수 있습니다. 서버 중단으로 searching 상태가 남으면 5분 후 다시 요청할 수 있습니다.

공식 제조사/인증기관/정부/연구 출처에서 정확한 제품 1개 기준의 절감 값·단위·비교 기준이 있어야 합니다. 출처 원문 숫자 및 단위를 확인하며 퍼센트나 총 배출량으로 절감량을 계산하지 않습니다. 데이터가 없으면 NULL로 남깁니다. 구매별 미확인 스냅샷만 보충하고 기존 확인된 기록을 중복 반영하지 않습니다. 이는 AI가 검색 인용을 대조하는 자동 조사이며 독립적인 환경 검증·LCA를 대신하지 않습니다.

개발자 테스트 구매는 요청대로 Gemini·바코드를 호출하지 않고 DB에 이미 있는 환경 근거를 반영합니다. 데이터 없는 제품으로는 구매 수는 확인할 수 있지만 환경점수·순위는 만들지 않습니다. 임의 수치 주입은 하지 않았습니다.

### 월간 순위와 보상

한국 시간의 인증 완료 월로 집계합니다. 각 항목을 그 달 최고값으로 나눈 0~100 점수의 평균입니다. 월 전체 양수 데이터가 있는 항목을 공통 분모로 쓰고 개인 누락 항목은 기여 없음으로 처리합니다. 모든 항목에 근거가 없는 참여자는 구매 수만 표시하고 순위는 제외합니다. 개발 모드에서는 개발자 테스트 구매도 포함하며 명시적으로 표시합니다. 개발 모드 해제 시 월간 순위에서 테스트 구매는 제외됩니다.

동점은 공동 순위이며 점유한 보상 순위 몫을 균등 분할합니다. 개발자만 월간 수익을 입력합니다. 수익 70%를 보상 풀, 나머지를 운영비로 배분하고 보상 풀 내 50/30/20%를 1~3위에 적용합니다. 원 미만과 공석 몫은 미배분금으로 표시합니다. 실제 광고·클릭/시청 추적·현금 지급은 없습니다.

웹검색 공통 파일은 `backend/exa_search.py`입니다. DB 확장 전 eco.before_full_flow.db 백업을 생성합니다. 추가 패키지는 없으며 기존 requests를 사용합니다. 계정·구매 데이터는 유지합니다.

외부 서비스 제한: 웹검색에는 EXA_API_KEY, 이미지 인증에는 GEMINI_API_KEY가 필요합니다. UPCitemdb 무료 API에는 요청 한도와 미등록 품목이 있습니다. 실제 검색 결과나 환경 수치가 없을 때 성공처럼 샘플을 대신 표시하지 않습니다.

공식 참고: [OpenCV BarcodeDetector](https://docs.opencv.org/5.0/main_modules/objdetect_barcode.html), [UPCitemdb](https://upcitemdb.com/api), [Exa Deep Search](https://exa.ai/docs/reference/search).


### Gemini 요청 제어 수정

검색과 JSON 정리는 별도 요청이지만, 각 성공 응답을 15분 보관해 결과 정리 실패 후 웹 검색부터 반복하지 않습니다. 이미지 인증 원본/응답은 이 캐시에 저장하지 않습니다. 같은 로컬 API 키로 진행되는 Gemini 요청은 DB 임대 잠금으로 중복 실행을 막습니다. SDK 자동 재시도는 1회 시도(재시도 없음) 설정을 유지합니다.

429 발생 시 Google의 QuotaFailure/RetryInfo에서 제한 종류와 대기 시간을 읽습니다. 할당량 0, 분당·일일 제한, 상세 미제공을 구분합니다. 상세가 없으면 사용량 초과로 단정하지 않습니다. 대기 중 추가 요청은 로컬에서 차단하고 자동 재호출하지 않습니다. 배치 수집은 429 및 키/모델/권한 오류에서 남은 검색을 중단합니다. 이 처리는 호출 낭비와 잘못된 안내를 개선하며 외부 서비스의 429 자체를 해제하지는 않습니다.

추가 DB 테이블 gemini_request_state, gemini_response_cache는 첫 요청 때 생성됩니다. 키 원문이나 이미지 원본은 저장하지 않습니다. 키의 단방향 해시만 요청 조정 범위로 사용합니다. `crawlingproducts.py`는 별도 기존 크롤링 파일이며 Gemini를 호출하지 않습니다. 이 앱은 해당 스크립트를 실행하지 않습니다.


## 추천·구매 인증 보완

추천점수는 가격 40% + 특징 40% + 인증/근거 20%입니다. 가격은 최저가/해당 가격 비율을 사용하며 미확인 가격에는 점수를 주지 않습니다. 특징 1~4개는 60/75/85/90점, 인증 시 최소 80점입니다. 인증/근거는 인증 100점, 특징 출처 50점, 미확인 0점입니다. 실제 환경효과 평가가 아니라 검색 편의용 규칙이며 용량·묶음 수량은 정규화하지 않습니다. 제품 카드의 별도 근거 버튼은 제거했지만 DB 출처는 보존합니다.

구매 인증번호 발급에는 주문 이미지 SHA-256이 필요합니다. 5분 내 제출해야 하며 처리 중 요청은 잠그고, 동일 성공 요청은 기존 구매를 반환합니다. 사진에서 읽은 번호·바코드를 서버에서 대조하고 취소·환불, 주문번호 미확인, 동일 사진 재사용을 차단합니다. AI 판정 반려 3회 시 번호를 무효화합니다. 원본 이미지는 저장하지 않습니다. 주문 한 건은 한 번 인증하며, 외부 주문 시스템 조회 없이 사진만 판독하므로 위조와 추후 취소까지 완전히 검증하지는 못합니다.

서버 재시작 시 verification_challenges에 이미지 해시·처리 잠금·시도 횟수·구매 연결 필드를 추가합니다. 기존 계정·구매 기록은 유지합니다.

## 상품 없이 개발자 시연

기존 서버를 종료한 뒤 Exa/Gemini 키가 설정된 터미널에서 `./run_demo.command`로 두 로컬 서버를 개발 모드로 켭니다. woodglue로 로그인하면 기존 실제 화면을 그대로 사용합니다.

실제 Exa 검색 → 실제 판매 제품 선택 → 가상 주문·제품 라벨·인증번호 종이 준비 → 실제 Gemini 검사 → 인증 기록 저장 → 예상 기여도 확인으로 이어집니다. 개발자 시연임을 표시하며 일반 사용자의 실제 구매 인증은 그대로 유지합니다.

이전 가상 시연 화면과 API는 제거했습니다. 이전 시연 전용 테이블이 있더라도 실제 통계에서 조회하지 않습니다.

### 실제 인식 기술을 쓰는 개발자 시연

구매 인증 화면의 `실제 제품으로 가상 구매 인증`에서 제품을 선택하고 `2. 가상 주문·제품·인증번호 종이 준비`를 누릅니다. 준비된 주문 이미지·제품 라벨과 인증번호 종이 PNG로 `3. 실제 이미지 분석으로 인증하기`을 누르면 됩니다. 제품·종이 이미지를 다운로드해 촬영한 파일로 교체할 수도 있습니다.

Gemini가 두 이미지를 실제로 판독합니다. 서버가 종이에서 읽은 4자리 번호와 발급 번호, 주문번호를 대조하고 통과해야 DEVELOPER_TEST 구매로 저장합니다. Gemini API 키와 사용량이 필요합니다. 실물·종이 대체 자료 허용은 개발자 시연에만 적용하며 일반 사용자 인증 조건은 유지합니다. API와 인증 처리는 DEVELOPMENT_MODE + developer 역할을 다시 확인합니다. 개발자도 같은 상품은 한 번만 인증되므로 재시연 시 내 가상 구매 기록 관리에서 시연 기록을 초기화합니다.

인증 생략 버튼은 화면에서 제거했습니다. 기존 개발자 전용 우회 API는 호환성을 위해 유지합니다. 시연 자료는 실제 주문·실물 사진이 아니며 PNG에 명시되어 있습니다.


## 2026-09-30 점검

일반/개발자 계정의 5개 화면, 로그인·권한·로그아웃, 추천 캐시, 실제 OpenCV 시연 바코드 인식, 구매 중복 방지, 환경 기록 단일 반영, 공동 순위·보상 합계, 개발자 기록 초기화를 임시 DB에서 확인했습니다. 기존 DB는 읽기 전용 무결성 검사와 복사본의 마이그레이션으로 확인했습니다. 외부 API 키가 없는 실행 환경이므로 Exa/Gemini는 대체 응답을 사용했으며, 실제 외부 응답 품질·서비스 한도는 별도 확인이 필요합니다.

일부 잘못된 검색 후보만 제외하도록 개선하고 기존 제품의 이름·설명을 갱신합니다. 이미지 크기를 디코딩 전에 검사합니다. 가상 샘플 제품은 일반 인증·외부 환경 조사·개발자 인식 시연에서 제외합니다. 환경 조사 실패 후 5분간 중복 요청을 막습니다. 테스트 구매가 실제로 포함된 월에만 랭킹 안내를 표시합니다.

## 문헌 기반 예상 기여도

`backend/impact_estimates.py`에서 대나무 수동 칫솔·헤드 교체형 수동 칫솔·리필 샴푸의 참고 시나리오를 계산합니다. 계산식·출처·적용 가정은 기여도 화면에 표시합니다. 실제 선택 제품의 검증값이 아니며 수량/용량 미확인 시 명시된 기준 사용량만 계산합니다. 다른 유형과 근거 없는 항목은 NULL입니다.

서버 시작 시 `impact_estimates`를 추가하고 기존 인증 구매에도 적용 가능한 추정 기준을 저장합니다. purchase_id가 기본키이므로 중복되지 않고 구매 삭제 시 함께 삭제됩니다. 기존 제품 확인값은 수정하지 않습니다. 확인값이 생긴 항목은 추정 합산에서 제외합니다. 추정치는 월간 랭킹·보상에 사용하지 않습니다. 추가 외부 API나 패키지는 필요하지 않습니다.

참고 출처: [칫솔 LCA 2020](https://discovery.ucl.ac.uk/10111617/3/Ashley_LCA%20toothbrush%20BDJ%20revisedL.pdf), [헤드 교체 연구 2024](https://link.springer.com/article/10.1007/s44274-024-00119-0), [Glenroy/PTIS 샴푸 포장 비교 2020, p44](https://www.glenroy.com/wp-content/uploads/2022/11/STANDCAP-Pouch-Lifecycle-Comparison-Nov2020_FORMATTED_FINAL3.pdf).

## 안드로이드 · 같은 와이파이 테스트

기존 `run_demo.command`로 FastAPI를 실행한 상태에서 별도 터미널에 `zsh run_phone.command`를 실행합니다. 출력되는 8503 안내 페이지에서 공개 테스트 인증서를 다운로드하고 안드로이드 설정의 CA 인증서 설치를 직접 진행합니다. 이후 출력되는 HTTPS 8502 주소로 접속합니다. 카메라 권한은 사용자가 휴대폰 브라우저에서 허용합니다.

인증서 개인 키는 `.local/phone_tls/`에만 생성되며 이 폴더는 Git에서 제외됩니다. 안내 서버는 공개 인증서와 안내 페이지만 제공합니다. 운영체제의 신뢰 저장소를 자동 변경하지 않습니다. 인증서는 테스트 종료 후 휴대폰에서 삭제합니다. 8502·8503은 현재 와이파이 IP에만 바인딩하며 FastAPI 8000은 루프백에 유지합니다. 외부 터널·포트포워딩은 사용하지 않습니다. 와이파이 IP가 바뀌면 실행기를 다시 켜고 새 주소로 접속합니다.

모바일 브라우저의 사이트 카메라에는 HTTPS 보안 컨텍스트가 필요합니다: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia
